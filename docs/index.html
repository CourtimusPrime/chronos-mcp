Agent inbox for Gmail & Calendar

Chronos syncs multiple Google accounts into a single queryable SQLite database and exposes everything through an MCP server — so your AI agents can read, search, and act on email and calendar data without cloud round-trips.

Everything agents need,

📬

Multi-account Gmail sync

Register any number of Gmail accounts under one daemon. All threads and messages land in one database.

📅

Google Calendar sync

Events, attendees, and recurrence rules synced incrementally. Full-text search across event titles and descriptions.

🔍

Full-text search (FTS5)

SQLite FTS5 indexes on messages and events. Sub-millisecond local search, no external search service needed.

🤖

MCP server

Exposes all data at localhost:7071/sse. Drop the config snippet into Claude, Cursor, or any MCP-compatible agent.

🗄️

Raw SQL access

Read-only SQL interface via POST /v1/query. Query the database directly from any HTTP client or agent tool.

⚡

Incremental sync

Gmail historyId and Calendar syncToken mean only deltas are fetched — fast, battery-friendly, and quota-safe.

Credentials

Stage credentials

chronos --use /path/to/credentials.json — points Chronos at your OAuth client JSON from Google Cloud Console.

Account

Add an account

chronos --add personal — opens the browser for OAuth2 consent. Repeat for as many accounts as you need.

03

Add Chronos to
your MCP client

.mcp.json — Claude Code · Cursor · any stdio client 
{
  "mcpServers": {
    "chronos": {
      "command": "chronos",
      "args": ["--mcp-stdio"]
    }
  }
}
claude_desktop_config.json — SSE / daemon mode 
// requires: chronos --start
{
  "mcpServers": {
    "chronos": {
      "url": "http://localhost:7071/sse",
      "transport": "sse"
    }
  }
}
Stdio mode (recommended)

chronos --mcp-stdio starts an embedded stack — sync engine, internal HTTP API, and MCP interface all in one process. No separate daemon needed. The agent launches it on demand.

SSE / daemon mode

Run chronos --start to get a long-lived daemon with HTTP API on :7070 and MCP/SSE on :7071. Useful when multiple clients share one sync process.

What you get

12 MCP tools: search messages, read threads, list and create calendar events, raw SQL queries, trigger syncs — all local, no cloud round-trips.

04

All commands
at a glance

Command Description
--use CREDENTIALS_PATHStage an OAuth credentials JSON for the next --add call
--add ALIASRegister a new account (opens browser for consent)
--remove ALIASRemove an account and its data
--listList all registered accounts
--test ALIASVerify account tokens are valid
--mcp-stdioStart embedded MCP server on stdio — no daemon needed, use in .mcp.json
--start [--http-port N] [--mcp-port N]Start the sync daemon (HTTP API + SSE MCP + background sync)
--stopClean shutdown — preserves synced data
--statusShow sync status for all accounts
--sync [ALIAS] [--type full|incremental]Trigger a manual sync
Note: --mcp-stdio is the recommended agent integration — no daemon required. Ctrl+C during --start wipes synced data but preserves accounts; use chronos --stop for a clean daemon shutdown.
